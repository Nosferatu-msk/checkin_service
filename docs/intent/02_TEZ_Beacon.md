# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## BLE-маяк для системы контроля присутствия

**Версия документа:** 1.0
**Дата:** 04.11.2026
**Протокол:** Bluetooth Low Energy (BLE) 4.2+ / 5.0
**Формат рекламы:** iBeacon (Apple)

---

## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1. Назначение устройства
BLE-маяк — стационарное устройство, устанавливаемое в контролируемой зоне (помещении, на этаже, в зоне объекта). Устройство транслирует в эфир BLE-пакеты стандарта iBeacon, которые принимаются мобильными приложениями сотрудников.

### 1.2. Варианты реализации
В рамках проекта предусмотрены **два варианта** реализации маяка:

| Параметр | Вариант А (основной) | Вариант Б (прототип) |
|----------|----------------------|----------------------|
| Описание | Готовый промышленный маяк | Самодельный на ESP32-C3 |
| Модель | Например: MBeacon, iBeacon CR2032 с AliExpress | ESP32-C3 SuperMini |
| Питание | CR2032 / CR2477 | USB 5V (для тестов) |
| Срок работы | 1-2 года | Часы/дни (от CR2032) |
| Прошивка | Закрытая, настройка через родное приложение | Своя, Arduino IDE / ESP-IDF |
| Назначение | Промышленная эксплуатация | Отладка ПО, тестирование |

## 2. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ (ОБЩИЕ ДЛЯ ОБЕИХ ВАРИАНТОВ)

### 2.1. Протокол вещания
Маяк должен транслировать **только** BLE-пакеты в формате iBeacon.

#### 2.1.1. Структура iBeacon-пакета
| Поле | Размер | Описание |
|------|--------|----------|
| Flags | 3 байта | 0x02 0x01 0x04 (LE General Discoverable, BR/EDR Not Supported) |
| Length | 1 байт | 0x1A (26 байт) |
| Type | 1 байт | 0xFF (Manufacturer Specific Data) |
| Company ID | 2 байта | 0x004C (Apple Inc., little-endian) |
| Beacon Type | 2 байта | 0x0215 (iBeacon) |
| Proximity UUID | 16 байт | Уникальный идентификатор маяка |
| Major | 2 байта | Дополнительный идентификатор (группа) |
| Minor | 2 байта | Дополнительный идентификатор (точка) |
| TX Power | 1 байт | Калибровочное значение RSSI на 1 метре (знаковое, dBm) |

#### 2.1.2. Диапазоны полей
- **UUID:** формат `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` (128 бит).
- **Major:** 0–65535 (рекомендуется использовать как ID объекта или этажа).
- **Minor:** 0–65535 (рекомендуется использовать как ID помещения/зоны).
- **TX Power:** от -100 до +20 dBm (калибруется при установке).

### 2.2. Параметры вещания
| Параметр | Значение по умолчанию | Диапазон настройки |
|----------|----------------------|---------------------|
| Интервал рекламы (Advertising Interval) | 1000 мс | 100 мс – 10 000 мс |
| Мощность передатчика (TX Power) | 0 dBm | -40 … +4 dBm |
| Формат | iBeacon | Только iBeacon |

**Рекомендации по интервалу:**
- Для объектов с высокой проходимостью: 500–1000 мс.
- Для объектов с редкими посещениями: 2000–5000 мс (экономия батареи).

### 2.3. Передача уровня заряда батареи
Стандарт iBeacon **не поддерживает** передачу заряда батареи. Для реализации этой функции используется **альтернативный пакет**:

#### 2.3.1. Вариант реализации
Маяк чередует два типа пакетов:
1. **iBeacon-пакет** (основной) — передаётся 9 раз из 10.
2. **Custom Manufacturer Data** — передаётся 1 раз из 10, содержит:
   - Company ID: `0xFFFF` (зарезервирован для тестирования)
   - Payload: `[Battery_Level (1 байт, 0-100), Firmware_Version (2 байта)]`

**Альтернатива:** Использовать маяки с поддержкой протокола **Eddystone-TLM** (Google), который штатно передаёт заряд батареи, температуру и время работы.

### 2.4. Индикация
- Светодиодный индикатор — **отключён** в рабочем режиме (экономия энергии).
- Включается только в режиме настройки (кнопка на корпусе) на 30 секунд.

## 3. ТРЕБОВАНИЯ К ВАРИАНТУ А (ГОТОВЫЙ МАЯК)

### 3.1. Закупаемые модели (рекомендации)
- **MBeacon V4** (Россия) — с поддержкой Eddystone-TLM.
- **Generic iBeacon CR2032** с AliExpress (поиск: "BLE iBeacon configurable").
- **Minew Technologies BE03** — промышленный вариант.

### 3.2. Обязательный функционал
1. Настройка UUID, Major, Minor через мобильное приложение производителя (по BLE).
2. Настройка интервала вещания.
3. Настройка TX Power.
4. Передача уровня заряда батареи (через Eddystone-TLM или custom-пакет).
5. Работа от элемента CR2032 не менее **12 месяцев** при интервале 1000 мс.
6. Корпус с возможностью крепления (скотч 3M, винты, магнит).

### 3.3. Процесс ввода в эксплуатацию
1. Администратор включает маяк (вытаскивает изоляционную полоску / нажимает кнопку).
2. Через приложение производителя считывает MAC-адрес и проверяет заводской UUID.
3. Перепрошивает UUID/Major/Minor в соответствии с планом объекта.
4. Регистрирует маяк в админ-панели системы (привязывает к зоне).
5. Устанавливает маяк в проектное положение.
6. Калибрует TX Power (опционально): замеряет RSSI на расстоянии 1 метр, вносит значение в маяк.

### 3.4. Процесс массового развёртывания
**Для партии из 50+ маяков:**

1. **Подготовка:**
   - Скачать шаблон `template_beacons.xlsx` из админ-панели.
   - Заполнить список маяков: MAC-адрес, UUID, Major, Minor, зона установки.

2. **Настройка маяков:**
   - **Вариант А (промышленные маяки):** использовать приложение производителя с функцией массового BLE-сканирования и настройки (например, MBeacon Config Tool).
   - **Вариант Б (ESP32-C3):** единая прошивка для всех маяков, уникализация через BLE-сервис (подключение с ноутбука/телефона, запись UUID/Major/Minor в NVS).

3. **Массовый импорт:**
   - Загрузить заполненный Excel-файл в админ-панель (`POST /api/admin/import/excel`).
   - Система автоматически создаст записи в таблице `beacons` с привязкой к зонам.

4. **Массовая калибровка (опционально):**
   - Установить все маяки в проектное положение.
   - Пройти с мобильным приложением по всем зонам, автоматически замерить RSSI на 1 м.
   - Обновить `tx_power` в БД через админ-панель.

5. **Проверка:**
   - Сканировать все маяки через nRF Connect или админ-панель.
   - Убедиться, что все маяки обнаруживаются и имеют корректные UUID/Major/Minor.

## 4. ТРЕБОВАНИЯ К ВАРИАНТУ Б (ПРОТОТИП НА ESP32-C3)

### 4.1. Аппаратная конфигурация
| Компонент | Модель / Описание |
|-----------|-------------------|
| Микроконтроллер | ESP32-C3 SuperMini (или Seeed XIAO ESP32C3) |
| Питание (прототип) | USB 5V (через повербанк) |
| Питание (финал) | CR2477 + LDO (MCP1700-33) |
| Антенна | Встроенная (PCB) |

### 4.2. Программное обеспечение
- **Среда разработки:** Arduino IDE 2.x или PlatformIO.
- **Библиотеки:** ESP32 BLE Arduino (официальная от Espressif).
- **Язык:** C++.

### 4.3. Алгоритм работы прошивки
```
setup():
  1. Инициализация BLE-стека.
  2. Конфигурация iBeacon с жёстко заданными UUID/Major/Minor/TX_Power.
  3. Запуск BLE-рекламы.
  4. Отключение Wi-Fi, Bluetooth Classic, UART (для экономии).
  5. Переход в режим минимального потребления.

loop():
  1. Пустой цикл (delay 10000 мс).
  2. Вся работа выполняется аппаратным BLE-контроллером в фоне.
```

### 4.4. Энергопотребление (ESP32-C3 SuperMini)
| Режим | Ток |
|-------|-----|
| BLE-реклама (интервал 1000 мс) | 15-25 мА |
| Глубокий сон (deep sleep) | ~5 мкА |
| **Средний ток (прототип, USB)** | ~20 мА |

**Важно:** 
- От CR2032 (225 мАч) такая плата проработает **~10 часов**.
- От CR2477 (1000 мАч) — **~2 дня** (не 3-4 месяца, как ошибочно указано в некоторых источниках).
- Для месячной работы необходим ток ≤ 1 мА, что требует:
  - Deep sleep между рекламными событиями (проснуться → передать → уснуть).
  - Специализированный BLE-чип (nRF52810, ток ~5 мкА в рекламе).
  - Увеличение интервала рекламы до 5-10 секунд.

**Реалистичный прототип:**
- Интервал рекламы: 5 секунд.
- Deep sleep между передачами.
- Средний ток: ~0.5 мА.
- От CR2477: ~2 месяца работы.

### 4.5. Процесс прошивки
**Единая прошивка для всех маяков (рекомендуется):**

1. **Подготовка прошивки:**
   - В коде `main.cpp` задать дефолтные значения UUID/Major/Minor (например, все нули).
   - Реализовать BLE-сервис с characteristics для записи UUID/Major/Minor/TX_Power.
   - Хранение конфигурации в NVS (Non-Volatile Storage).

2. **Первичная прошивка:**
   - Подключить модуль к ПК через USB.
   - Скомпилировать и загрузить единую прошивку через Arduino IDE.
   - Все маяки получают одинаковую прошивку.

3. **Уникализация (после сборки):**
   - Подключиться к маяку по BLE с ноутбука/телефона (специальное приложение-конфигуратор).
   - Записать уникальные UUID/Major/Minor в NVS через BLE-сервис.
   - Перезагрузить маяк — новые значения вступают в силу.

**Альтернатива (не рекомендуется):** жёсткая прошивка с уникальными значениями для каждого маяка (требует 50 разных сборок для 50 маяков).

### 4.6. Рекомендации по маркировке
На корпусе каждого маяка должна быть наклейка с:
- Инвентарным номером (ID из БД).
- UUID (сокращённо, последние 8 символов).
- Major.Minor.
- Датой ввода в эксплуатацию.
- QR-кодом с UUID (для быстрого сканирования при установке).

## 5. ТРЕБОВАНИЯ К РАЗМЕЩЕНИЮ И ЭКСПЛУАТАЦИИ

### 5.1. Место установки
- Высота: 2.0–2.5 метра от пола (оптимально для распространения сигнала).
- Избегать: металлических поверхностей, бетонных колонн в непосредственной близости, источников помех (Wi-Fi роутеры, микроволновки).
- Крепление: двусторонний скотч 3M, стяжки, винты (в зависимости от модели).

### 5.1.1. Условия эксплуатации
**Для разных сценариев развёртывания:**

| Сценарий | Температура | Влажность | IP-рейтинг | Примечания |
|----------|-------------|-----------|------------|------------|
| Офис | +18...+25°C | 30-60% | IP20 (минимум) | Обычный пластиковый корпус |
| Склад | -10...+40°C | 20-80% | IP42 | Усиленный корпус, защита от конденсата |
| Улица | -40...+50°C | 0-100% | IP67 | Водонепроницаемый корпус, морозостойкая батарея |

**Важно:** CR2032 при -10°C теряет 30-50% ёмкости. Для низких температур использовать литиевые батареи (CR2) или специализированные маяки с расширенным температурным диапазоном.

### 5.1.2. Покрытие одного маяка
**Ожидаемое расстояние обнаружения (RSSI > -75 dBm):**

| Окружение | Расстояние | Рекомендуемый интервал рекламы |
|-----------|------------|--------------------------------|
| Открытое пространство | 15-20 м | 1000 мс |
| Офис с перегородками | 8-12 м | 1000 мс |
| Бетонные стены | 5-8 м | 500 мс |
| Металлические конструкции | 3-5 м | 500 мс |

**Влияние человеческого тела:** тело человека на частоте 2.4 ГГц даёт затухание 5-15 дБ. Если маяк установлен на высоте 2.0-2.5 м, а сотрудник ходит внизу — тело может экранировать сигнал. **Рекомендация:** тестировать в реальных условиях с людьми в зоне покрытия.

### 5.2. Калибровка RSSI
После установки маяка необходимо:
1. Встать на расстоянии 1 метр от маяка.
2. Замерить RSSI мобильным приложением (nRF Connect).
3. Записать значение в поле `TX Power` маяка и в БД системы (для точного определения расстояния).

### 5.3. Обслуживание
- Замена батареи: по уведомлению из системы (уровень заряда < 15%).
- Периодическая проверка: 1 раз в квартал (визуальный осмотр, проверка крепления).
- Ведение журнала обслуживания (в админ-панели).

### 5.4. Мониторинг состояния маяков
- Мобильное приложение отправляет список обнаруженных маяков каждые 5 минут.
- Сервер обновляет `beacons.last_seen_at` для каждого маяка.
- **Алерты:**
  - Если маяк не обнаруживается > 24 часов — статус "Неисправен" и уведомление администратору.
  - Если заряд батареи < 15% — уведомление "Низкий заряд" с указанием местоположения маяка.
- **Процесс замены батареи:**
  1. Администратор получает уведомление с указанием маяка и его местоположения.
  2. Открывает карточку маяка в админ-панели, нажимает "Заменить батарею".
  3. Физически заменяет батарею.
  4. Нажимает "Подтвердить замену" — маяк помечается как "Обслужен".
  5. Проверяет, что маяк снова передаёт данные (в течение 10 минут).

## 6. ТРЕБОВАНИЯ К БЕЗОПАСНОСТИ

1. Маяк **не должен** поддерживать BLE-подключения (только broadcast).
2. Отсутствие возможности удалённой перепрошивки по воздуху (защита от несанкционированного изменения UUID).
3. Корпус — антивандальный (для публичных объектов).
4. **Защита от клонирования:**
   - Каждый маяк имеет уникальный BLE MAC-адрес (аппаратный, неизменяемый).
   - Мобильное приложение передаёт MAC-адрес вместе с UUID на сервер.
   - Сервер проверяет соответствие MAC-адреса и UUID (таблица `beacons.mac_address`).
   - При несовпадении — событие `beacon_clone_detected` в `fraud_logs`.
5. **Физическая защита:** для публичных объектов — корпус с пломбой, вскрытие которой приводит к уничтожению маяка.

## 7. КРИТЕРИИ ПРИЁМКИ

| № | Критерий | Метод проверки |
|---|----------|----------------|
| 1 | Маяк обнаруживается приложением nRF Connect | Сканирование в радиусе 10 м |
| 2 | UUID/Major/Minor соответствуют заявленным | Сравнение с БД |
| 3 | Интервал вещания соответствует настройкам | Анализ пакетов в nRF Connect |
| 4 | RSSI на расстоянии 1 м соответствует TX Power | Замер в контролируемых условиях |
| 5 | Время работы от батареи соответствует ТЗ | Ускоренные испытания / расчёт |
| 6 | Корпус имеет крепление | Визуальный осмотр |
| 7 | MAC-адрес передаётся вместе с UUID | Проверка в мобильном приложении |
| 8 | Телеметрия батареи передаётся (Eddystone-TLM или custom-пакет) | Анализ пакетов в nRF Connect |
| 9 | Стабильность интервала (отклонение < 5%) | 24-часовой тест |
| 10 | Работа при низком заряде батареи (< 20%) | Тест с искусственным разрядом |
| 11 | Работа при отрицательных температурах (для склад/улица) | Камера с контролируемой температурой |

## 8. ПЛАН РАЗРАБОТКИ (ВАРИАНТ Б)

| Этап | Срок | Результат |
|------|------|-----------|
| 1. Закупка ESP32-C3 SuperMini | 1 неделя | Аппаратная база |
| 2. Написание базовой прошивки | 3 дня | Работающий iBeacon |
| 3. Оптимизация энергопотребления | 3 дня | Минимальный ток |
| 4. Тестирование с мобильным приложением | 1 неделя | Интеграция |
| 5. Проектирование финальной версии (nRF52) | Параллельно | ТЗ на промышленный маяк |

**Итого:** ~3 недели до рабочего прототипа.
